# Skill Review — 内容质量审计

检查 skill 的 frontmatter 和正文，确保每一条信息都有存在价值，没有重复、没有废话、没有结构缺陷。

## 边界 / 不适用场景

- 检查的是普通文档、代码、PRD → 错配 skill
- skill 还在草稿阶段、用户明确要求"先写出来再改" → 先完成再 review
- 只改一个错别字或一个标点 → 直接改，不需要跑完整 review

## 审计维度（6 项必查）

按以下顺序逐项检查，每一项都要给出"通过 / 有问题 + 具体位置 + 改法"：

### 1. Frontmatter 完整性

检查项：
- `name` 是否存在且唯一
- `description` 是否存在
- `description` 是否包含**两个要素**：做什么 + 何时调用（缺少任一项都是 P0）

### 2. Description 精准度

检查项：
- 是否超过 200 字符（过长则触发条件不够醒目）
- 是否包含空话（"提升效率"、"更好的体验"等无信息量表述）
- 是否明确写出触发场景（"当用户要求 X 时调用"）

### 3. 正文与 Description 重复

检查项：
- 正文是否有"什么时候用"章节 → 与 description 重复，应改为"边界 / 不适用场景"
- 正文是否有重复 description 的段落 → 直接删除
- 正文是否有"这个 skill 用于 XXX"的开场白 → 与 description 重复，直接删除

### 4. 边界 / 不适用场景

检查项：
- 是否有"边界 / 不适用场景"章节（缺少则是 P1）
- 是否列出至少 3 条不适用场景
- 每条是否给出"什么情况下不要用 + 应该转向哪里"

### 5. 结构清晰度

检查项：
- 是否有明确的模块划分（必做步骤、输出结构、核心规则等）
- 是否有"不做什么"章节（缺少则是 P1）
- 是否有跨 skill 衔接说明（如果该 skill 属于流程中的一环）

### 6. 内容冗余

检查项：
- 是否有空话、套话、正确的废话（"确保质量"、"提高效率"等）
- 是否有重复表达同一意思的段落
- 是否有可以压缩为表格或列表的长段落

## 输出结构

按优先级分级输出问题，每条都包含：**位置 + 问题描述 + 改法**：

| 等级 | 含义 | 处理方式 |
|------|------|----------|
| **P0** | 结构性缺陷，影响 skill 触发或执行 | 必须修复 |
| **P1** | 质量缺陷，会降低 skill 效果 | 强烈建议修复 |
| **P2** | 可选优化，让 skill 更精炼 | 作者自行决定 |

## 修复原则

- **能删就删**：如果一条信息删除后不影响理解，就删
- **能压就压**：如果一段话可以压成一句话或一个表格项，就压
- **能指向就指向**：如果正文内容与 description 重复，删正文留 description
- **不重写正文**：只挑问题和给改法，不替作者重写（除非作者明确要求）

## 不做什么

- 不重写 skill 正文（只给改法）
- 不评价 skill 的设计思路（只检查内容质量）
- 不检查 skill 是否能正确触发（那是运行时问题，不是内容问题）
- 不给"整体不错"的客套反馈
