# 后端规范

> 本项目的后端通用开发规范，包括项目结构、分层规范、公共能力等。

---

## 一、项目结构

```
jeecg-boot/
├── jeecg-boot-base-core/          # 核心基础组件
│   └── src/main/java/org/jeecg/
│       ├── common/
│       │   ├── api/vo/            # 通用响应类（Result）
│       │   ├── system/base/       # 基础类（JeecgEntity、JeecgController）
│       │   └── util/              # 工具类（OssBootUtil、MinioUtil 等）
│       └── config/                # 配置类
│
├── jeecg-module-system/           # 系统模块（公共能力）
│   ├── jeecg-system-biz/          # 系统业务实现
│   │   └── src/main/java/
│   │       ├── org/jeecg/modules/
│   │       │   ├── oss/           # OSS 文件存储模块
│   │       │   ├── system/        # 系统管理（用户、角色、权限、字典等）
│   │       │   └── message/       # 消息通知模块
│   │       └── com/cssz/modules/  # 新业务模块目录（新模块放这里）
│   └── jeecg-system-start/        # 系统启动模块
│
└── jeecg-server-cloud/            # 微服务版本（可选）
```

**新业务模块位置**：`jeecg-boot/jeecg-system-biz/src/main/java/com/cssz/modules/{模块名}/`

## 三、分层开发规范

### 3.1 Entity 层

**基类**：`CsEntity`（`com.cssz.base.CsEntity`，继承自 `JeecgEntity`）
- 继承 `JeecgEntity` 的字段：id、createBy、createTime、updateBy、updateTime
- 自带扩展字段：deleteBy、deleteTime、ownerOrgCode

**扩展字段规范**：
- `owner_org_code`（VARCHAR(64)）：所有者部门编码，默认取创建人的部门编码

**枚举值字段规范**：
- 性别、状态、类型等枚举值字段，必须从系统数据字典中取值，禁止硬编码
- 使用 `@Dict` 注解绑定字典编码

```java
@TableName("表名")
@Schema(description = "实体描述")
public class XxxEntity extends CsEntity {
    
    @Dict(dicCode = "sex")  // 枚举值，使用字典示例
    private Integer sex;

    @Schema(description = "字段描述")
    private String fieldName;
}
```

### 3.2 Mapper 层

```java
@Mapper
public interface XxxMapper extends BaseMapper<XxxEntity> {
    // 继承 BaseMapper，自动获得 CRUD 方法
}
```

### 3.3 Service 层

**接口**：
```java
public interface IXxxService extends IService<XxxEntity> {
    void businessMethod(String param);
}
```

**实现**：
```java
@Slf4j
@Service
public class XxxServiceImpl extends ServiceImpl<XxxMapper, XxxEntity> implements IXxxService {
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void businessMethod(String param) {
        // 业务逻辑
    }
}
```

### 3.4 Controller 层

```java
@Slf4j
@RestController
@RequestMapping("/模块/资源")
public class XxxController {
    
    @Autowired
    private IXxxService xxxService;
    
    @RequiresPermissions("{模块}:{资源}:list")
    @GetMapping("/list")
    public Result<IPage<XxxEntity>> queryPageList(
            XxxEntity query,
            @RequestParam(name = "pageNo", defaultValue = "1") Integer pageNo,
            @RequestParam(name = "pageSize", defaultValue = "10") Integer pageSize,
            HttpServletRequest req) {
        
        QueryWrapper<XxxEntity> queryWrapper = QueryGenerator.initQueryWrapper(query, req.getParameterMap());
        Page<XxxEntity> page = new Page<>(pageNo, pageSize);
        IPage<XxxEntity> pageList = xxxService.page(page, queryWrapper);
        
        return Result.ok(pageList);
    }
    
    @RequiresPermissions("{模块}:{资源}:add")
    @PostMapping("/add")
    public Result<String> add(@RequestBody XxxEntity entity) {
        xxxService.save(entity);
        return Result.ok("添加成功");
    }
}
```

## 五、删除规范

**默认使用软删除**，除非明确必须物理删除（如临时数据、日志清理等场景）。

- 软删除通过 `delete_by`（删除人）和 `delete_time`（删除时间）字段标记，`delete_time` 非空时视为已删除
- 查询时需过滤已删除记录：`queryWrapper.isNull("delete_time")` 或判断 `entity.getDeleteTime() != null`
- 删除操作示例：

```java
@PostMapping("/delete")
public Result<?> delete(@RequestParam String id) {
    XxxEntity entity = xxxService.getById(id);
    if (entity == null) {
        return Result.error("数据不存在");
    }
    entity.setDeleteBy(UserUtil.getCurrentUsername());
    entity.setDeleteTime(new Date());
    xxxService.updateById(entity);
    return Result.OK();
}
```

- 若确需物理删除，必须在代码注释和 PR 中说明理由

## 七、已有公共能力

### 7.1 文件存储（OSS/MinIO）

**工具类**：
- `org.jeecg.common.util.oss.OssBootUtil` - 阿里云 OSS
- `org.jeecg.common.util.MinioUtil` - MinIO

**常用 API**：
```java
// 上传文件
String url = OssBootUtil.upload(MultipartFile file, String bizPath);

// 获取原始 URL（用于数据库存储）
String originalUrl = OssBootUtil.getOriginalUrl(url);

// 删除文件
OssBootUtil.deleteUrl(url);

// 生成预签名下载 URL（带有效期）
String downloadUrl = OssBootUtil.generatePresignedUrl(bucketName, objectKey, expiration);
```

**参考实现**：`org.jeecg.modules.oss.controller.OssFileController`

### 7.2 通用响应类

**类名**：`org.jeecg.common.api.vo.Result<T>`

**标准用法**：
```java
// 成功响应
return Result.ok(data);
return Result.ok("操作成功");

// 错误响应
return Result.error("操作失败");
return Result.error(500, "服务器内部错误");

// 分页响应
Result<IPage<Entity>> result = new Result<>();
result.setSuccess(true);
result.setResult(pageData);
return result;
```

### 7.3 权限控制

**注解**：`@RequiresPermissions`（Apache Shiro）

**命名规范**：`模块:资源:操作`

**示例**：
```java
@RequiresPermissions("audit:report:list")
@RequiresPermissions("audit:report:add")
@RequiresPermissions("audit:report:edit")
@RequiresPermissions("audit:report:delete")
```

### 7.4 数据字典

**控制器**：`org.jeecg.modules.system.controller.SysDictController`

**使用方式**：
```java
// 通过字典编码获取字典项
List<DictModel> dictList = sysDictService.queryDictItemsByCode("dict_code");

// 前端调用
GET /sys/dict/getDictItems/{dictCode}
```

### 7.5 文件上传

**通用上传控制器**：`org.jeecg.modules.system.controller.SysUploadController`

**复用方式**：
```java
@PostMapping("/upload")
public Result upload(@RequestParam("file") MultipartFile file) {
    String url = OssBootUtil.upload(file, "upload/business");
    return Result.ok("上传成功").result(url);
}
```

## 八、开发检查清单

开发新功能时，检查以下事项：

- [ ] Entity 继承 `CsEntity`
- [ ] Mapper 继承 `BaseMapper<Entity>`
- [ ] Service 接口继承 `IService<Entity>`
- [ ] Service 实现继承 `ServiceImpl<Mapper, Entity>`
- [ ] Controller 使用 `@RestController` 和 `@RequestMapping`
- [ ] Controller 使用 `@RequiresPermissions` 控制权限
- [ ] Controller 使用 `Result<T>` 返回统一格式
- [ ] 使用 `@Schema` 添加接口文档
- [ ] 使用 `@Slf4j` 记录日志
- [ ] 事务方法添加 `@Transactional`
- [ ] 数据库表设计符合 [数据库规范](./数据库规范.md) 要求
- [ ] 配置文件中添加必要的配置项
